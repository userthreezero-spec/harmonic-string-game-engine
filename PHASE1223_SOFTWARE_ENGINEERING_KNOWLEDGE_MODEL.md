# Phase 1223: Software Engineering Knowledge Model

## 1. Knowledge Domains Covered
- **Software Architecture:** Layered, modular, client/server, event-driven, hexagonal, clean architecture, domain-driven design, dependency inversion, coupling vs cohesion.
- **Architecture Decision Making:** Quality attributes (performance, reliability, scalability, extensibility, security, maintainability), architectural tradeoffs, decision records.
- **Software Construction:** Component decomposition, API design, concurrency, persistence, serialization, build systems, linkers, packaging, runtime initialization/shutdown.
- **Integration & Testing:** Unit, component, integration, system, soak, performance, and acceptance testing. Distinguishes component existence from true runtime integration.
- **System Evolution:** Refactoring, migration, strangler pattern, technical debt, architectural drift detection.

## 2. Structural Schema
Every knowledge item is stored with structured fields:
- `knowledge_id`, `source_id`, `source_url`, `topic`, `concept`, `principles`, `patterns`, `tradeoffs`, `failure_modes`, `confidence`, `provenance`.
